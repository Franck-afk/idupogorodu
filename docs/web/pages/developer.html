Техническая документация

Паттерны, контракты, точки расширения и инварианты кода. Всё, что нужно знать перед изменением плагинов idpg-core и idpg-city-admin.

Паттерны кода

Singleton везде

Каждый компонент — класс-синглтон: private function __construct() + public static function instance(). Обращение к состоянию — только через instance().

File-load init

Синглтоны, которым нужны хуки Carbon Fields (carbon_fields_register_fields, dispatch на init priority 0), создаются на этапе загрузки файла, а не в idpg_core_init() — иначе подписка опаздывает.

Настройки-класс

Паттерн IDPG_Banner_Settings: defaults() → get_settings() (wp_parse_args) → типизированные геттеры с clamp → sanitize_settings( $raw ) → handle_save() (nonce + redirect + flash).

Версионирование

Каждый плагин — константа IDPG_*_VERSION; ассеты версионируются ей же (для cache-busting). Миграции меты — через option idpg_meta_migration_version.

Точки расширения (хуки)

Actions / filters проекта
/* Добавить позицию вывода баннера (тема вызывает в шаблоне): */
add_action( 'idpg_banner_position', 'my_render', 10, 1 );

/* Добавить вкладку на страницу «Иду по городу»: */
add_filter( 'idpg_widget_areas_admin_tabs', function ( $tabs ) {
	$tabs['my-tab'] = array(
		'label'    => 'Моя вкладка',
		'callback' => 'my_tab_render',
	);
	return $tabs;
} );

/* Сбросить кэш баннера при своих событиях: */
do_action( 'save_post_event', $post_id );  // уже purge_cache

Жизненный цикл баннера

Request → HTML
front-page.php
  └─ do_action( 'idpg_banner_position', 'hero' )
       └─ IDPG_Current_Event_Banner::render( 'hero' )
            ├─ should_render(): enabled? hero? is_front_page?
            ├─ render_paid_html()
            │    ├─ get_paid_events(): transient idpg_paid_banner_ids_{city}
            │    │    └─ WP_Query( _idpg_banner_approved=yes, poster, даты )
            │    └─ 1 событие → render_single_html()
            │       N событий → карусель + data-interval/data-autorotate
            └─ render_html()
                 └─ get_current_event(): transient idpg_current_event_id_{city}
                      └─ render_single_html( $event )
                           ├─ override: banner_title / banner_text / button_text
                           ├─ fallback: get_the_title / get_the_excerpt (+обрезка)
                           ├─ chips · dates · meta-line · fav · btn
                           └─ <a style="--idpg-banner-h:{height}px">

Carbon Fields

  • Bootstrap: after_setup_theme priority 5 с гардом function_exists( 'carbon_get_theme_option' ) — плагин boot'ит раньше темы, дубль пропускается
  • Контейнеры: 5× post_meta для события, 1× для площадки, 1× user_meta для реквизитов организатора
  • Машинный экспорт полей: docs/carbon-fields-export.json

REST API

  • Пространство idpg/v1, ~36 маршрутов: события, площадки, города, live-поиск, избранное, подписка, статистика организатора
  • У каждого маршрута — permission_callback; у каждого параметра — sanitize_callback
  • Nonce для JS: wp_create_nonce( 'wp_rest' )

Инварианты безопасности

Формы

wp_nonce_field() + wp_verify_nonce() / check_admin_referer(); POST-обработчики висят на admin_init и выходят молча без своего action-поля

Escape / санитизация

Escape на выводе «как можно позже»: esc_html, esc_attr, esc_url, esc_textarea. Ввод — safelist вместо blocklist

Права

current_user_can( 'manage_options' ) в рендере И в обработчике; проверки с клиента не доверяем

Рекламный код

<script>/<iframe> в виджете рекламы — только при edit_theme_options (wp_kses с расширенным whitelist)

Тестирование

  • WP_UnitTestCase + фабрики; private-методы — через ReflectionMethod (см. render_single_html, should_render)
  • Контрактные тесты: HTML проверяется по подстрокам (name="idpg_banner_*", data-settings-panel) — ловят поломку формы без браузера
  • Обратная проба обязательна: тест должен падать при намеренной поломке правки
  • PHPCS: свой .phpcs.xml.dist + baseline на компонент; Windows-пути — через патчи bin/phpcs-patches/
