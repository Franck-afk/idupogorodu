Плагин idpg-core

Центральный плагин портала: контент-модель событий и площадок, мультигородность, REST API, авторизация, роли, баннер, виджеты, кэши и миграции. 42 класса, ~24 000 строк.

Актуальное состояние. Carbon Fields выпилен из плагина: мета переведена на нативный register_meta(), редактирование полей — через собственные вкладки IDPG_Event_Fields / IDPG_Venue_Fields. vendor/autoload.php больше не подключается, runtime-зависимостей в composer.json нет (только dev: phpunit + yoast/phpunit-polyfills). В теме осталось одно использование carbon_get_theme_option().

Bootstrap и константы

idpg-core.php — инициализация
define( 'IDPG_CORE_VERSION', '1.1.2' );
define( 'IDPG_CORE_FILE',    __FILE__ );
define( 'IDPG_CORE_DIR',     plugin_dir_path( __FILE__ ) );
define( 'IDPG_CORE_URL',     plugin_dir_url( __FILE__ ) );
define( 'IDPG_CORE_BASENAME', plugin_basename( __FILE__ ) );

// Город по умолчанию для фильтрации (терм таксономии city).
define( 'IDPG_DEFAULT_CITY_ID', 15 );

// Базовый URL внешнего API агрегатора билетов (заглушка).
define( 'IDPG_TICKET_API_URL', 'https://api.example.com/v1' );

// require_once всех class-*.php → idpg_core_init() на 'init'
  • Загрузка: require_once каждого класса в фиксированном порядке, затем add_action( 'init', 'idpg_core_init' )
  • Синглтоны, которым нужны ранние хуки, создаются на этапе загрузки файла (file-load init)
  • Деструктивность при удалении плагина — uninstall.php

Контент-модель

CPT event

Rewrite /afisha/, есть архив. Поля: даты (_idpg_start_date, _idpg_end_date), цены, билеты, сеансы (зеркало _idpg_sessions_json), флаги «бесплатно», «онлайн», «весь день».

CPT venue

Rewrite /venues/, есть архив. Поля: адрес, часы (зеркало), соцсети (зеркало).

Таксономии

event_category (/event-category/), age_rating (/age-rating/), city — иерархическая область→город→район (/gorod/).

Мета

Нативный register_meta() с auth_callback — запись через REST только для своих ключей; гарантия города и даты на save_post.
