Исправленные ошибки

Разбор двух критичных поломок: parse error в настройках баннера и «голая» стилизация баннера из-за расхождения CSS и HTML.

Баг 1 · Parse error в админке

Parse error: syntax error, unexpected fully qualified name исправлено

plugins/idpg-core/includes/class-banner-settings.php on line 423 — админка не открывалась.

Причина

Файл был повреждён скриптовой вставкой: реальные табы и переводы строк записались как литеральные \t и \n (backslash + символ). PHP интерпретировал \ перед табом как начало fully qualified name.

Зоны повреждения

  1. Строки 418–430: трижды дублированная $saved_meta + чужой блок $edit_slug/$editing (код из виджет-менеджера) с литеральными \t\t
  2. Строка 548: в HTML втиснута строка с литеральными \n\t\t\t\t + чужой блок if ( $editing ) с кнопкой «Отмена»

Исправление

  • Убран весь мусорный блок — осталась одна корректная $saved_meta = (int) get_user_meta( ... );
  • Кнопка сохранения очищена от хвоста с $editing/«Отмена»
  • Файл не был в git (untracked) — восстановление выполнено вручную

Баг 2 · Баннер без стилизации

Бейджи и кнопка баннера выводились «голыми» исправлено

CSS отставал от доработанного HTML баннера.

Диагноз

В коде баннер перешёл со старых классов __badge/__status--* на новые __chip--*, плюс добавились кнопка «Подробнее» и VIP-цена. В current-event-banner.css для новых классов не было ни одного правила — grep chip возвращал пусто.

Исправление

  • Дописаны стили __chips, __chip и всех модификаторов типов
  • Стиль взят из карточки события (templates.css) — те же hex-цвета
  • Добавлены кнопка __btn, VIP-акцент и мобильный адаптив
  • Скобки 59/59, все классы HTML покрыты

Метод диагностики

1. Локализация

Чтение файла вокруг строки из ошибки → обнаружены литеральные \t\t вместо табов.

2. grep по маркерам

Поиск \\t и \\n по всем PHP-файлам проекта — другие повреждения не найдены (3 вхождения легитимны: trim-строка, комментарий, тест).

3. Проверка git

Файл untracked — восстановление из репозитория невозможно, восстановлена логика вручную.

4. Верификация

php -l на PHP 8.2 и 8.3, повторный grep на мусор — чисто.

!

Выводы на будущее. Скриптовые вставки кода через heredoc без интерполяции опасны: \t/\n записываются буквально. Правки через инструменты редактирования файлов с валидацией. После массовых замен — php -l + grep по маркерам.
