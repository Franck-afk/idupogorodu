# IDPG Core Theme

**Иду по городу** — тема WordPress для сайта-афиши с управлением событиями и площадками.

---

## 📋 О проекте

Тема разработана для работы с плагином **IDPG Core** и предоставляет полноценный фронтенд для:
- Просмотра событий и площадок
- Авторизации пользователей
- Создания событий организаторами

### 2. Заглушка в синхронизации билетов

```php
// plugins/idpg-core/includes/class-ticket-sync.php:234
// TODO: Заменить на реальный base_url API агрегатора.
$base_url = defined( 'IDPG_TICKET_API_URL' )
    ? IDPG_TICKET_API_URL
    : 'https://api.example.com/v1';
```

**Проблема:**
- Cron-задача будет отправлять запросы на **несуществующий API** (`api.example.com`)
- Метод `build_api_url()` помечен как **ЗАГЛУШКА** (строка 221)

**→ Решение:**
1. Заменить `IDPG_TICKET_API_URL` в `wp-config.php` на реальный URL (например, API Biletix, Kassir и т.д.)
2. Доработать логику `build_api_url()` для разных сервисов

### 3. Отсутствует логотип для email-рассылки

```php
// plugins/idpg-core/includes/class-auth-emails.php:309
$this->logo_url = apply_filters(
    'idpg_email_logo_url',
    home_url( '/wp-content/uploads/email-logo.png' )
);
```

**Проблема:**
- В шаблонах писем (`render_email_template()`) используется логотип, но файла **`/wp-content/uploads/email-logo.png`** нет в проекте
- Писемы будут отображаться без логотипа

**→ Решение:** Загрузить логотип в `uploads/` или переопределить через фильтр `idpg_email_logo_url`

## 🟡 ПОТЕНЦИАЛЬНЫЕ ПРОБЛЕМЫ (нужна проверка/доработка)

### 4. Некорректная работа без JavaScript

**Проблема:**
- Страница `page-login.php` использует **AJAX** для отправки форм через `auth.js`
- Если JavaScript отключён, формы **не будут работать** (нет fallback на стандартную обработку WordPress)

**→ Решение:**
- Добавить fallback обработку форм через PHP (action в формах)
- ИЛИ показать сообщение пользователю о необходимости включить JS

---

### 5. Нескомпилированные SCSS файлы

**Проблема:**
- В `themes/idpg_core/assets/scss/` есть SCSS файлы:
  - `_variables.scss`, `_reset.scss`, `_typography.scss`
  - `_container.scss`, `_header.scss`
  - `_auth.scss`
  - `style.scss`
- В `assets/css/` только `editor-style.css` (для редактора WordPress)
- **Основные стили** подключаются из `style.css` в корне темы

**→ Решение:**
- Скомпилировать SCSS в CSS (`npm run build` или вручную)
- ИЛИ подключить SCSS напрямую (если поддерживается)

---

### 6. Node Modules в продакшене

**Проблема:**
- В теме есть папка `node_modules/` (600+ МБ)
- Это **увеличивает размер проекта** и не нужно в продакшене

**→ Решение:**
- Добавить `node_modules/` в `.gitignore`
- ИЛИ удалить папку перед деплоем



**→ Решение:** Проверить совместимость полей между фронтендом и бэкендом

---

### 8. Отсутствие обработки CSRF для стандартных форм

**Проблема:**
- В `page-login.php` формы используют AJAX, но нет стандартной обработки через WordPress
- Если кто-то откроет страницу без JS, форма **не отправится**

**→ Решение:**
- Добавить action в тег `<form>` (например, `action="<?php echo esc_url( home_url( '/wp-login.php' ) ); ?>"`)
- Добавить скрытое поле с nonce

## 🚀 Быстрый старт

1. Установите WordPress
2. Активируйте плагин **IDPG Core**
3. Активируйте тему **idpg_core**
4. Исправьте критические проблемы (см. чек-лист)
5. Настройте константы в `wp-config.php`:
   ```php
   define( 'IDPG_DEFAULT_CITY_ID', 1 );
   define( 'IDPG_TICKET_API_URL', 'https://<реальный-агрегатор>.example.com/v1' );
   ```
   > ⚠️ Пока `IDPG_TICKET_API_URL` не задан реальным адресом (или содержит `example.com`), синхронизация билетов автоматически пропускается — cron не шлёт запросы на несуществующий API.
6. Не требуется создавать страницы вручную: `/login/`, `/reset-password/`, `/terms/`, `/privacy/` создаются автоматически при активации темы.
7. Настройте меню в WordPress
