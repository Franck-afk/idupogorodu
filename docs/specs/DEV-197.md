# DEV-197. Остатки прохода DEV-196 и 6 падений PHPUnit

> **Статус:** черновик
> **Карточка:** `docs/PROJECT.md` §22
> **Объём:** M

## 1. Задача

Полный прогон PHPUnit даёт **6 падений**, ни одно из которых не связано с кодом,
написанным в DEV-196, но все шесть лежат ровно там, куда DEV-196 указала руками
(§21.6, §22.1, §22.2). Пять из них — «санитайзер профиля проверен, а тесты всё
равно красные»: схема REST отвергает значения раньше колбэка и подменяет код
ошибки. Шестое — мёртвые правила `.dashboard__*`, которые §21.7 сознательно
оставила в `_dashboard.scss` и `style.css` с пометкой «их удаление вынесено
в DEV-197».

Задача закрывает остаток прохода: приводит список инициализации классов в
соответствие с новым файлом, снимает двойную валидацию профиля, удаляет мёртвый
CSS и пересобирает `style.css`.

## 2. Требования

1. **`IDPG_Organizer_Meta` описан в списке инициализации.** Класс использует
   статический `::init()`, который вызывается в конце своего файла
   (`class-organizer-meta.php:90`), поэтому место записи — `STATIC_INIT`
   (хук → метод), а не `SINGLETONS`: приватного статического `$instance`
   у класса нет.
2. **Схема `PUT /organizer/profile` не валидирует ИНН и `legal_type`.** Проверки
   остаются за `IDPG_Organizer_URL::sanitize_profile_input()` — единственным
   источником правил для REST и для no-JS формы (`page-organizer.php`).
3. **Код ошибки ИНН — `idpg_profile_invalid_inn`**, а не `rest_invalid_param`:
   отказ приходит из санитайзера, а не из `pattern` схемы.
4. **Пустой ИНН — не ошибка** (очистка поля), `legal_type` вне safelist
   сохраняется как `''`.
5. **Мёртвые правила `.dashboard__*` удалены** из `_dashboard.scss`; в теме
   (`*.php`, `*.js`) нет ни одного вхождения `dashboard__` (проверено: 0).
6. **`style.css` пересобран** штатной командой `npm run compile:css:apply`
   и совпадает с SCSS-деревом.
7. **Полный прогон PHPUnit без падений** (6 → 0), новых не появляется.
8. **Поведение и разметка кабинета не меняются:** классы `idpg-org-*`,
   `cabinet__*` и публичные правила `style.css` остаются на месте.

## 4. Границы — что НЕ делаем

- **Не переписываем** `_organizer.scss`, `organizer.js`, `section-*.php` —
  они закрыты DEV-196.
- **Не трогаем** `assets/css/organizer.css`: он собирается отдельным скриптом
  и от `style.css` не зависит.
- **Не заводим новые токены** `#16a34a`/`#d97706`: правила `.dashboard__*`,
  которым они принадлежали, удаляются целиком, поэтому токены остаются без
  потребителей. Токенизировать нечего.
- **Не меняем** `_dashboard.scss` сверх удаления: весь файл состоит из
  `.dashboard__*` и после чистки пуст, поэтому удаляется как партиал вместе
  с `@use 'pages/dashboard'` в `style.scss`.
- **Не подключаем** `pages/organizer` и `pages/venue-form` в `style.scss`
  (DEV-196, критерий 13).
- **Не правим** `docs/PROJECT.md (раздел 1)` §9: там отмечено, что
  `check:css` создан, а PHPUnit-сторож `Test_Css_Build` уже существует и
  покрывает это требование.
- **JS-стенд** (`tests/js-smoke/organizer-js-smoke.js`) не расширяем: он
  зелёный и не связан с падениями этой задачи (в §22.2 оставлен как
  отдельное пожелание, без карточки).
- **PHPCS** в кабинете (39 ошибок, §22.2) не чистим: к падениям не относится.
