# Спецификации задач

Здесь лежат спецификации (`DEV-XXX.md`) для задач объёма **M и L**.
Шаблон — [`TEMPLATE.md`](TEMPLATE.md). Для объёма S спецификация не нужна,
достаточно карточки в `docs/PROJECT.md`.

## Зачем

Карточка в `docs/PROJECT.md` отвечает на «что делать». Спецификация — на
«как именно и как это проверить». Ключевые отличия:

- **«Границы» (§4)** — что сознательно НЕ делаем. Без этого следующий заход
  примет границу за недоделку.
- **«Критерии приёмки» (§3)** — проверяемые утверждения, а не пожелания.
- **«Обратная проба» (§6)** — доказательство, что критерии ловят дефект,
  а не описывают текущее поведение.

## Процесс

1. Карточка в `docs/PROJECT.md` (проблема + требование).
2. Спецификация `docs/specs/DEV-XXX.md` по шаблону. Имя файла = номер карточки.
3. Реализация строго по §5 спецификации. Отклонение → сначала правится
   спецификация.
4. Приёмка по критериям §3.
5. Обратная проба: замер «до», замер «после», проверка мутацией.
6. Документация — в том же коммите, что и код.

Правило закреплено в [`AGENTS.md`](../../AGENTS.md) §13.
