# DEV-02. Синхронизация билетов: устойчивость и журнал (часть 1 — без реального API)

> **Статус: реализовано (часть 1, без реального API); приёмка пройдена 19.10.2026.**
> Реальный адаптер API агрегатора и приёмка с живым агрегатором — блокер карточки
> (нет доступов/документации от владельца). См. §7.

Карточка: `docs/PROJECT.md`, раздел 2, DEV-02. Объём: M.

## 1. Проблема и цель

`IDPG_TICKET_API_URL` = `https://api.example.com/v1` (заглушка). Требование карточки:
получение статуса по `_idpg_external_id`, маппинг в `_idpg_ticket_status`, обработка
ошибок/таймаутов, повторные попытки, логирование в журнал плагина.

Реальный API агрегатора недоступен, поэтому реализуется часть, не зависящая от чужих
доступов: устойчивость запроса (повторы, бэкофф, таймаут), настоящий журнал и точки
расширения под будущий адаптер. Цель: cron больше не «молчит»; сбой не портит событие;
диагностика видна в админке; адаптер подключается фильтрами без правки класса.

## 2. Решение (что делаем)

1. **Журнал плагина** — новый `IDPG_Logger` (`includes/class-logger.php`): кольцевой
   буфер последних 100 записей в опции `idpg_log_recent` (**autoload=false**), методы
   `log()/get_recent()/clear()`, уровни `info|warning|error`; сообщение обрезается до
   500 символов и чистится от тегов; запись — `time`, `level`, `source`, `message`.
   Подключение — в `idpg-core.php` перед `class-ticket-sync.php`.
2. **Делегирование лога.** `IDPG_Ticket_Sync::log()` перестаёт быть no-op и пишет в
   `IDPG_Logger` (источник `ticket-sync`); диагностика сбоев попадает в журнал.
3. **Повторные попытки** запроса статуса одного события: до `MAX_ATTEMPTS = 3`
   (фильтр `idpg_ticket_sync_max_attempts`). Пауза — **экспоненциальный бэкофф**:
   база `RETRY_DELAY = 2` с, ×2 на каждую следующую попытку (2 с, затем 4 с),
   потолок `RETRY_MAX_DELAY = 8` с; фильтр `idpg_ticket_sync_retry_delay` задаёт
   базу (в тестах — 0 или 1 с). Фактическая пауза пишется в журнал. Повтор на:
   `WP_Error` (таймаут/сеть), HTTP 429, HTTP ≥ 500. Без повтора: прочие 4xx,
   успешный ответ.
4. **Таймаут запроса** — `REQUEST_TIMEOUT = 15` с, фильтр `idpg_ticket_sync_timeout`.
5. **Фильтры-точки расширения** под реальный адаптер: `idpg_ticket_sync_api_url`
   (URL запроса), `idpg_ticket_sync_response_data` (приведение произвольного JSON к
   ожидаемому виду), `idpg_ticket_sync_status_map` (дополнение карты статусов).
6. **Guard заглушки `example.com`** сохранён: проверяется **после** фильтра URL, т.е.
   фильтром можно легально подменить заглушку боевым адресом.
7. Контракты DEV-18 не меняются: `run_sync()` — void, `run_sync_counting()` /
   `run_sync_now()` — int.

## 3. Критерии приёмки

| № | Критерий | Чем проверяется |
|---|---|---|
| 1 | Журнал пишет и ограничен | `test_logger_writes_and_caps`: запись с источником/уровнем; 105 → 100, старейшая вытеснена; опция не в автозагрузке |
| 2 | Транзиентный сбой лечится повтором | `test_retry_on_transient_errors`: 3 запроса, статус применён с 3-го |
| 3 | Постоянный сбой не портит событие | `test_all_attempts_fail_keeps_status`: 3 запроса, мета прежняя, error в журнале |
| 4 | 4xx — без повторов | `test_client_error_no_retry`: 1 запрос, error в журнале |
| 5 | Заглушка `example.com` не шлёт запросы | `test_stub_url_no_request`: 0 запросов, warning «заглушка» |
| 6 | Маппинг статуса и хук | `test_status_change_updates_meta_and_fires_hook`, `test_unknown_status_keeps_meta` |
| 7 | Фильтры работают | `test_api_url_filter` (URL подменён); `test_response_data_filter` (формат `{"state":"…"}` через фильтр); `test_status_map_filter` (кастомный статус применяется); `test_timeout_default` / `test_timeout_filter` (15 с и подмена на 7) |
| 8 | Регресс и гигиена | полный PHPUnit зелёный (в т.ч. старый `test-ticket-sync.php`); PHPCS ядра exit 0 (baseline **не** расширялся); `php -l` новых/правленых файлов |
| 9 | Бэкофф растёт | `test_exponential_backoff`: база 1 с → в журнале «повтор через 1 с.», затем «повтор через 2 с.»; статус применяется третьей попыткой |

## 4. Границы (что НЕ делаем)

- **Не реализуем реальный адаптер** API агрегатора — нет доступов/документации.
- **Не меняем контракты** DEV-18 (`run_sync()` void; `run_sync_counting()`/`run_sync_now()` int).
- **Не трогаем** тему `idpg_core`, `deploy.sh`, конфиг CI.
- **Не удаляем** guard заглушки `example.com`.
- **Не добавляем** записей в baseline PHPCS — только сокращаем устаревшие.
- **Не вводим** файловый лог и `error_log()` (AGENTS §11).

## 6. Обратная проба

Замер «до» снят по текущему коду (19.10.2026): повторов нет — при транзиентном
сбое ровно **1** HTTP-запрос и статус не обновляется; `log()` — no-op,
`get_option('idpg_log_recent')` не существует, диагностики нет нигде;
guard `example.com` работает (0 запросов) — это сохраняемое поведение.

| Проверка | До | После | Что ломали в мутации | Реакция |
|---|---|---|---|---|
| Повторы (§3.2, §3.3) | 1 запрос, без повтора | 3 запроса, статус применён с 3-го | `max_attempts = 1` | `test_retry_on_transient_errors`: 1 запрос вместо 3 — падает |
| Журнал (§3.1, §3.2) | записи нет (no-op) | 2 warning + info; буфер 100 | вернуть `log()` в no-op | журнальные проверки: 0 warning/error — падают |
| Заглушка (§3.5) | 0 запросов | 0 запросов (guard сохранён) | снять guard `example.com` | `test_stub_url_no_request`: 3 запроса на заглушку — падает |
| Фильтры (§3.7) | точек расширения нет | 4 фильтра, каждый проверен тестом | снять фильтр status_map / response_data / api_url; снять фильтр таймаута; подменить дефолт таймаута на 30 | `test_status_map_filter` / `test_response_data_filter` / `test_api_url_filter` / `test_timeout_filter` / `test_timeout_default` — падают (статус не применился; 0 запросов; 15 с вместо 7; 30 с вместо 15) |
| 4xx (§3.4) | без повторов, но и без журнала | 1 запрос + error в журнале | повторять и на 4xx (`>= 400`) | `test_client_error_no_retry`: 3 запроса вместо 1 — падает |
| Бэкофф (§2.3) | пауза фиксированная 2 с | база ×2 (1 с → 2 с в тесте), потолок `RETRY_MAX_DELAY = 8` с | убрать удвоение (фиксированная пауза) | `test_exponential_backoff`: обе паузы «1 с.» — падает (нет «повтор через 2 с.») |

Итог обратной пробы: **10 из 10 мутаций пойманы** (по одной на каждый фильтр, плюс
таймаут-дефолт, бэкофф, повторы, журнал, заглушка, 4xx). Зелёный полный прогон:
488 тестов / 1310 утверждений / 1 skip — OK.
