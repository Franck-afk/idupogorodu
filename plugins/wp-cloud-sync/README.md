# WP Cloud Sync

Плагин синхронизации сайта WordPress с Яндекс.Диском: загрузка файлов темы и плагинов в облако, а также скачивание их на удалённый сервер по крону.

## Структура

```
wp-cloud-sync/
├── wp-cloud-sync.php                        # Главный файл плагина (точка входа)
└── includes/
    ├── class-wp-cloud-sync.php              # Основной класс: настройки, OAuth, загрузка файлов
    └── class-wp-cloud-sync-downloader.php   # Загрузчик: скачивание файлов из облака по крону
```

## Возможности

- Страница настроек в меню «Настройки» → «WP Cloud Sync».
- Авторизация через Яндекс OAuth (Client ID / Client Secret → access_token).
- Инкрементальная синхронизация файлов темы и кастомных плагинов на Яндекс.Диск.
- Параллельная обработка файлов (3 AJAX-воркера, окна по 8 файлов).
- Режим загрузчика: скачивание файлов из облака на удалённый сервер по крону (каждые 5 минут).
- Просмотр, очистка и экспорт логов (TXT/CSV/HTML/JSON).

## Исправленные ошибки (07.08.2026)

### 🔴 Критическая: бесконечный цикл пустых окон

**Симптом:** после обработки последнего реального окна воркеры продолжали резервировать пустые окна (`start=85, end=85`), каждый раз инкрементируя счётчик активных воркеров. Условие `done` никогда не наступало, синхронизация «зависала» на ~30+ секунд, лог забивался тысячами бесполезных строк `RESERVE/DECR`.

**Исправление:**

- В `run_batch()` добавлена проверка пустого окна: если `$start >= $total`, воркер **не инкрементирует** счётчик активных воркеров, а сразу переходит к финальной проверке завершения.
- Выделен метод `finalize_batch()` — единая точка финальной проверки `done` под локом. Используется и для пустых окон (без декремента), и для реальных окон (с декрементом). Устранено дублирование логики.

### 🟠 Средняя: чтение файлов целиком в память

**Симптом:** `upload_file()` читал файл целиком через `file_get_contents()`. При `MAX_FILE_SIZE = 1 ГБ` это приводило к фатальной ошибке нехватки памяти.

**Исправление:** загрузка переведена на потоковую передачу через cURL:

- `http_request()` поддерживает опцию `'file'` — открывает файл через `fopen()` и передаёт его в cURL через `CURLOPT_UPLOAD` + `CURLOPT_INFILE` + `CURLOPT_INFILESIZE`.
- `upload_file()` передаёт путь к файлу и его размер вместо чтения в память.

### 🟡 Убрана временная debug-диагностика

Удалены все `TEMP-диагностика` логи (DONE-EXIT, RESERVE, DECR, LOCK-ACQ), которые засоряли production-лог внутренней информацией.

## Требования

- WordPress 6.0+
- PHP 7.4+
- Расширение cURL
